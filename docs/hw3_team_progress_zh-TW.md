## 系統怎麼運作？

1. 先均勻選 8 個時間點。影片 reader 以實際畫面時間戳解碼，回傳影格 ID、要求時間與實際時間。
2. 把影格與時間戳、問題、剩餘預算及過去決策組成 prompt。
3. 模型回傳 JSON，包含候選選項、證據時間、缺少的證據、信心與動作。
4. 若要補看，只能要求一個合法區間中的 4 或 8 張新影格。只有整批解碼成功且沒有重複，才更新觀察預算。
5. 若要提早回答，需有有效選項、已觀察的證據時間、沒有待補證據，且信心至少 0.80。這是操作規則，不是校準後的答對機率。
6. 最多觀察 24 張、最多四輪。無效 JSON 或不合法動作會記錄失敗，不偷偷重試。

這套控制與 runner 已有程式。還沒確認的是：真實 Qwen 是否能穩定遵守這份 prompt 與 JSON 格式，以及整條流程在正式影片題目上表現如何。

## 正式評估仍照 HW1 的研究問題走

預計在 Video-MME 挑 100 題，中、長影片各 50 題（依可取得資料調整），由兩位審閱者確認能否只靠畫面作答，記錄排除原因及一致性。主模型仍規劃 Qwen3-VL-8B-Instruct，不用聲音或字幕。

所有方法需先固定同一套模型、processor、畫面設定、作答提示與解碼條件，再比較準確率、實際影格數、呼叫數、tokens 與耗時。Adaptive 和 Uniform-24 以相同題目配對；always-use-24 用來區分選幀與早停的效果。

`configs/main.json` 仍有未填的版本與推論設定，所以目前還不是完成凍結的正式實驗。報告可以寫清楚已實作、如何驗證、接下來怎麼比較，不能填入尚未測得的準確率。

## 組員怎麼接手？

組員不需要登入實驗機器。先看 `docs/architecture.md`、`ROADMAP.md` 和這份說明；需要查實作時，對照 `src/watch_wisely/` 與 `tests/`。

在自己的環境重跑離線測試：

```sh
python -m venv .venv
# 啟用虛擬環境後：
python -m pip install -e ".[video,test,stats-test]"
python -m pytest tests -q
python scripts/check_configs.py
python scripts/smoke.py
```

這些檢查不需要模型權重或正式資料集。`scripts/smoke.py` 明確標為 synthetic，它測控制流程，不會產生模型答案或研究結果。

接下來建議先分三件事，實際負責人再由組內確認：

- 檢查並凍結 processor、prompt、JSON 與結果欄位，先讓共同流程完成一題真實問答。
- 整理資料清單與人工篩選表，準備正式評估。
- 接 CLIP encoder、統一基準作答介面，再做選幀與早停比較。
